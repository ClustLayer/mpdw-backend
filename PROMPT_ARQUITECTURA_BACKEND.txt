<sad_binding_decisions>
  Digest of the SAD decisions that most often get violated by code generators.
  Each line is binding; the SAD prevails if it differs.

  ARCHITECTURE (ADR-001, §6.2, §6.4–§6.6)
  - Layers: Aplicación (DRF views + serializers: HTTP, whitelist validation,
    status codes, authentication/permission classes) → Negocio (services per
    module: use cases, totals, state machines, transactions) → Persistencia
    (repositories over the Django ORM; hand-written SQL only in reports and
    the ETL; only the mandatory sede filter as a rule) → Datos (Supabase).
  - One Django app per module M01…M13 under apps/{modulo}/ with models.py,
    serializers.py, views.py, services.py, repositories.py, migrations/.
    Shared ports and state enums live in contratos/. ETL lives in etl/.
  - Order inside a module: View → Service → Repository (enforced with
    import-linter, one contract per app: SAD §6.5.4 [Decidido]).
  - Ports only at the boundaries (mail/SendGrid, FileStorage/Supabase Storage,
    PDF, anti-bot) plus the inter-module ports InventoryPort (M04),
    CashPort (M08), SalesReadPort (M06) and AuditPort (M10). The M06↔M08
    cycle is broken by two one-way ports.
  - A module reads only its own tables; foreign data goes through ports (PR-3).
  - M09 reads only the `analitica` schema through a read-only DB alias
    (role mpdw_bi) with parameterized SQL; no ORM models for that schema.
    Only the ETL writes it.

  TRANSACTIONS AND INTEGRITY (ADR-005, §8.3, §8.5, §9.3)
  - One transaction per use case (TX-01…TX-11): explicit transaction.atomic in
    the service; ATOMIC_REQUESTS stays False; READ COMMITTED; no SERIALIZABLE.
  - Stock: conditional atomic UPDATE with F() ("... WHERE cantidad_actual >= q");
    lock order ascending id_inventario; retry on deadlock. Consecutives: counter
    row with select_for_update + UNIQUE (id_sede, serie, numero_factura).
  - Optimistic concurrency: integer `version`; filter(pk=..., version=...)
    .update(version=F('version') + 1); zero rows ⇒ HTTP 409; weak ETag on
    reads; If-Match (or version in the body) on writes.
  - Idempotency: unique `clave_idempotencia` column on the entity plus an
    Idempotency-Key header; a retry returns the already-created resource.
  - Nothing external inside a transaction: e-mail via transaction.on_commit;
    files uploaded BEFORE the transaction, orphan cleanup afterwards.
  - Money is Decimal / numeric(14,2), never float. Prices, totals, stock and
    cash reconciliation are computed only on the server (K-07).
  - State catalogs defined once (shared enums in contratos/) + CHECK in the DB.
  - Logical deletion only; kardex and Auditoria are append-only; corrections
    via compensating movements (K-06, PR-6).
  - Instants stored as timestamptz (USE_TZ=True); business date in
    America/Bogota (S-01); currency COP.

  AUDIT (ADR-008, NF-07)
  - A central AuditPort is called by the business layer INSIDE the same
    transaction — never Django signals, never DB triggers as the capture
    mechanism. Fields: user, action, entity, entity id, IP, before/after as
    JSON, reason, result, correlation id.
  - mpdw_app has only INSERT/SELECT on Auditoria; a trigger rejects
    UPDATE/DELETE. Sanitize passwords, tokens and full account numbers.

  AUTHENTICATION (ADR-006, §10.3, §7.3.1)
  - Access token: JWT of 15 min (configurable) validated by simplejwt or PyJWT
    as a DRF authentication class; claims limited to sub, rol, sid, jti, exp —
    never permissions.
  - Refresh token: opaque, ≥ 128 bits, stored only as a hash in
    Sesiones_usuario, rotated on every use, reuse ⇒ revoke the whole family,
    60-min sliding inactivity with a 7-day absolute cap; delivered in a cookie
    HttpOnly; Secure; SameSite=Strict; Path=/api/v1/auth; Origin check on the
    cookie-based endpoints (refresh, logout).
  - Lockout after 5 failures / 15 min (configurable); generic error message; no
    self-registration (BR-09); password ≥ 10 chars with an uppercase letter
    and a digit; Argon2id through a subclass of Argon2PasswordHasher
    (≥ 19 MiB, 2 iterations, parallelism 1).
  - Recovery: 30-min single-use token stored as a hash; identical response
    whether or not the e-mail exists. 2FA: e-mail code, admin only, 10 min,
    3 attempts, one use. SendGrid adapter: timeout 10 s, 3 retries with growing
    wait, executed after commit; failure is audited, response unchanged.
  - Custom user model on Usuarios (AbstractBaseUser); no contrib.admin.

  AUTHORIZATION (ADR-007, §10.4, Annex A)
  - Permission = (módulo, acción), e.g. CAJA:CERRAR_JORNADA. Effective =
    Usuario_permiso override if present, else Rol_permiso, else DENY.
    Evaluated on every request; no cache; none in the JWT.
  - Sede scope enforced in the repository layer from an authorization context
    (Usuario_sede); global roles skip it explicitly. Object scope (an Empleado
    sees their own invoices) and state scope (open shift only). Deny by
    default; 403/404 without revealing existence.

  API (§9.1, §9.3, K-02)
  - /api/v1, JSON only (no browsable API in production). Pagination `page` and
    `size` (20/50/100) returning total, page, size. Status codes 400, 401, 403,
    404, 409, 422, 429, 500. Error body {codigo, mensaje, detalles[],
    idCorrelacion} from one central exception handler; correlation header on
    every response and in logs; no stack traces in production.
  - Serializers with an explicit field whitelist — never fields = '__all__'.
  - OpenAPI via drf-spectacular, exported to docs/openapi.yaml, checked in CI.
  - Health: GET /api/v1/health/live and /api/v1/health/ready (Supabase and
    Storage), no sensitive data.
  - Throttles: DRF throttles whose counter lives in Django's DatabaseCache
    (createcachetable). Never LocMemCache; never Redis.
  - Public endpoints (M12): rate-limited per IP, strict schemas, client prices
    and totals ignored (AD-21, T-07).
  - Import/export capped at 5 000 rows ⇒ 422; import never overwrites; one
    transaction per batch inside the request; no worker (I-05, ADR-010).

  DATA ACCESS AND SUPABASE (ADR-003, §8.3, §8.8)
  - API → pooler in transaction mode (6543), role mpdw_app,
    DISABLE_SERVER_SIDE_CURSORS=True, psycopg 3 prepare_threshold=None,
    CONN_MAX_AGE=0, sslmode=require, no session-level settings (schema names
    written in SQL, instants in timestamptz).
  - Migrations and ETL use a session-type connection with mpdw_migrate /
    mpdw_etl. A read-only alias with mpdw_bi serves M09 and the BI endpoint.
  - pg_trgm enabled; indexes per §8.8 (PostgreSQL does not index FK columns
    automatically).
  - No Supabase Auth, no supabase-js, no anon key, nothing from the browser to
    Supabase.

  FILES (ADR-011, §10.6, I-04)
  - FileStorage port with two Supabase Storage implementations: public bucket
    `medios-publicos` (re-encoded images + thumbnails) and private bucket
    `adjuntos-privados` (never public; authenticated download streamed by the
    API). Validate real MIME + extension + size (≤ 5 MB, configurable); UUID
    file names; store SHA-256; re-encode images with Pillow; serve with
    X-Content-Type-Options: nosniff and Content-Disposition.

  ETL (ADR-013, §8.11, §7.5)
  - `python manage.py run_etl [--desde --hasta]` in etl/. One transaction with
    pg_try_advisory_xact_lock (session-level locks do not work behind a
    transaction pooler); set-based SQL with schema names; statement_timeout;
    INSERT ... ON CONFLICT DO UPDATE into `analitica` (ventas_diarias,
    movimientos_diarios, productos_top, inventario_alerta, corrida_etl);
    result recorded in corrida_etl; days grouped in America/Bogota over
    timestamptz; Python orchestrates and measures, it does not load operational
    data in memory; no pandas/dbt/Airflow. The analitica DDL is a RunSQL
    migration run by mpdw_migrate.

  DELIVERY (ADR-012, §13, K-03)
  - One image for API and ETL; non-root; gunicorn sync workers; Render builds
    from the repository; migrations run by the pipeline (mpdw_migrate), not at
    container start; configuration only from the environment; structured JSON
    logs to stdout with the correlation id.
